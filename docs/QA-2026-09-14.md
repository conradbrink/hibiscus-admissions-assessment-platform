# End-to-end QA run — 14 September 2026

Every parent door, every active campus, every admissions stage and every
staff role, walked in a headless browser against a local stack and then
walked again after the fixes. This page is the record: what was run, what
broke, what was changed, and what a reader should still not assume.

## How it was run

- **Stack.** Postgres 16 with all 95 migrations replayed from empty
  (`supabase/tests/replay_local.sh`), PostgREST, a small gateway standing
  in for Supabase Auth and Storage, and `next dev` with every provider on
  its `dev` adapter (email to the outbox table, payments through the
  simulate screen, messaging and AI recorded and not sent). The dev seed
  (`supabase/seed/dev_phase2.sql`) supplied the Stage 1–6 paper, a sample
  Block 7 fee schedule and a draft ruleset; the drain created six weeks of
  weekday sessions at every active campus.
- **Accounts.** One staff account per role (super admin, admissions
  manager, admissions staff, finance, assessor, management, content author)
  and three campus-scoped accounts (Block 7, Phase 2, a Broadhurst
  manager). Parents have no accounts: every parent step used the magic
  link from the email the system sent.
- **Scripts.** Playwright journeys, one per door, plus a campus matrix, a
  role matrix, a takeover probe, upload-edge, mobile-width and dashboard
  probes. They live outside the repository (they depend on the local
  stack); what they found is pinned by the unit tests and security cases
  listed under each fix.
- **Checks before the commit.** `npm run typecheck`, `npm run lint`,
  `npm test` (821 tests), `npm run build`, `npm run check:nonce-safe`, and
  the full migration replay with the security (67 cases) and template
  coverage suites.

## Bugs found and fixed

Severity as the brief defines it: P0 security, data leak or inability to
submit; P1 a core workflow broken or wrong data; P2 a stage that works but
wrongly; P3 cosmetic or wording.

Not bugs, recorded so nobody chases them: the dev-mode `eval()` CSP console
error is React's development build, not the site; and a running `next dev`
does not pick up a *new* export added to an existing server-action module —
restart it, or the page keeps posting the old action under the new name.

## By design, and left as is

- A waitlisted family is approved from the applicant page's Decision tab;
  declining them from there is not offered (the school's rule that a child
  is not turned away through that form). Withdraw remains available.
- Offers at campuses without a fee schedule stop at `offer_draft` with a
  `configure_fees` task rather than sending an unpriced letter. Only Bana
  Tlokweng (seeded) and Block 7 (dev sample) have one.
- Zero-valued attention items are not listed on the dashboard.

## What remains untested

Real providers were not called: Resend, DPO Pay / PayGate, Supabase Storage
and Auth, the WhatsApp adapters and the Anthropic adapter ran on their
`dev` stand-ins, exactly as before this run. QR scanning and the signature
pad on a real tablet were not tried. Two people editing the same applicant
at once was exercised only as far as the engine's optimistic status check
(`status_conflict`), not as a browser race.
